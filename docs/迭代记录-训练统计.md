# 训练统计按招聘描述分组

日期：2026-11-13。基于主分支 e4c201798060e682e2c32add1efa01e6bcc681ba。

## 用户问题与验收目标

同一份简历针对不同招聘描述会得到不同规则分。旧统计只按岗位和评分方式分组，可能把更换招聘描述引起的差异展示为训练进步或退步。

验收目标：相同岗位、相同招聘描述的简历报告才能一起计算趋势；不同招聘描述分别展示；旧格式记录继续可读；面试原有分组行为保留。

## 实现

- 复用报告中已有的 description，不改数据库表结构，不重算或改写历史报告。
- 简历统计分组增加招聘描述；面试仍沿用类型、岗位、评分方式和难度。
- 分组选项显示招聘描述摘要，结果区显示完整内容，复用已有长文本样式。
- 没有招聘描述字段的旧格式报告按岗位预设关键词处理，与空 JD 报告归为一组。
- 配置测试仅替换 DeepSeek 相关环境变量，保留 Windows 系统环境，避免清空环境后 SSL 初始化失败。

招聘描述按保存的文本精确区分，不尝试推断两份不同 JD 是否语义相同。统计差值表示练习规则分的变化，不构成真实能力提升的证明。面试题目和模型等条件的可比性不属于本次修复范围。

新增两个工作流测试，先在旧实现运行：一项因不同 JD 仍混组失败，另一项因统计未返回招聘描述出错。修复后执行完整命令：

```powershell
python -m unittest discover -s tests -v

```

在 Windows、Python 3.12.14、pypdf 6.21.4 环境中，20 项自动化测试全部通过，无需预先初始化 SSL，也无需真实 API Key。

浏览器使用临时数据库并关闭 AI。同一正文依次针对 Python、Redis、Python 生成 57、17、57 分报告：Python 分组显示两次训练、变化 0 分；Redis 分组显示一次训练、不计算变化。原有历史入口与统计维度可见。390 像素窄屏下，普通 JD 和 3,000 字符长 JD 均未出现文档级横向溢出。
